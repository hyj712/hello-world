# 🎓 Streamlit 学习之旅 · 毕业总结与知识地图

> 从"为什么点新建会话不清空侧边栏"出发，历经 6 个实验室和一场官方 bug 狙击战。

## 一、心智模型（理解层——一切的基础）

1. **整脚本重跑**：Streamlit 每次交互都从头执行整个脚本；只有 `st.session_state` 能跨重跑存活，普通变量每轮"转世重生"。
2. **页面是照片，状态是真相**：改状态 ≠ 改画面；要刷新画面就 `st.rerun()` 重拍一张。
3. **输入框有自己的记忆**：每个 widget 在储物柜里有自己的格子（key 命名；不给 key 就是乱码名）。变量只是复印件。
4. **两个抽屉**：真相抽屉（代码随时读写）vs 输入框抽屉（出生后只认键盘）。两扇同步门：`value=`（出生瞬间：真相→框）、赋值语句（每轮：框→真相）。
5. **换身份证（动态 key）**：pop 只删"记忆"删不掉"人"（浏览器组件沿用旧值，官方 bug #16388）；换 key = 换新人，`value` 必然生效。

## 二、通用工程原则（任何语言/框架可迁移）

| 原则 | 一句话 | 本项目中的体现 |
|---|---|---|
| 单一数据源 | 一份数据只存一个地方 | partner_name 只住在真相抽屉 |
| 派生数据不存 | 能算出来的就不存 | system_prompt 用时拼 |
| 显示与数据分离 | 页面上的字 ≠ 数据 | yield 给别人看，reply_parts 留给自己 |
| 兼容旧数据 | 格式演进时读得动旧文件 | isinstance 判断新旧格式 |
| 配置提为常量 | 会变的东西别埋在代码里 | MODEL_NAME |
| 防御式编程 | 假设一切都会出错 | try/except、or ""、存在性检查 |
| 备份后手术 | 改大代码前先复制一份 | AI-partner_1_backup.py |

## 三、调试方法论（AI 时代最值钱的技能）

1. **不猜，数证据**：print 探针、`st.write(st.session_state)`。
2. **三份证据交叉定位**：终端输出 + 页面显示 + 状态值，互相印证。
3. **分层排查**：代码 → 逻辑 → 环境/框架。代码和逻辑都"对"时，去查官方 issue（#16388 就是这样抓到的）。
4. **最小复现**：把问题隔离进 10 行的小实验（lab 系列），不带着整个项目排查。
5. **先备份再动刀**。

## 四、AI API 通用知识（跨语言）

1. **messages 是时间线**：system + 历史 + 新消息，按顺序排。
2. **流式三层**：概念（边产生边消费）→ API（stream=True + delta 增量）→ 协议（SSE，未来学）。参数名和结构在 Python/JS/curl 里一模一样。
3. **delta ≠ message**：流式返回的是增量，完整回复是"过程"的产物。
4. **模型名是配置且会变**：deepseek-chat 已停用 → deepseek-v4-flash；永远查官方文档。

## 五、Python 技能点（本次新学）

- 生成器 `yield`：水龙头模型——"被拉一下，跑一小段，停在 yield"。
- `st.session_state` 的字典式操作：`in`、`pop`、`get`、`isinstance`。
- json 读写：`ensure_ascii=False`、`encoding="utf-8"`。

## 六、元学习方法（最重要的收获）

- **小实验隔离概念**：一个概念一个 lab，先观察后命名。
- **猜 → 验证 → 修正**：允许自己猜错（你的第③题、我的两处误判都是例子）。
- **亲手观察 > 听讲**：看一百遍不如 print 一遍。
- **敢于怀疑框架**：官方 bug 人人能踩，能定位它的是少数。

## 七、AI 时代：你的新定位

**对一半**：AI 让你不必当"代码打字员"（不用背 API、不用记得每个参数）。
**错一半**：你依然需要"专业"——只是专业的内容变了。

| AI 替你做的 | 永远要你做的 |
|---|---|
| 写出代码初稿 | 把需求说精确（规格化） |
| 解释代码、翻译语言 | 读懂、能改、能验证 |
| 提出方案 | 判断方案对错、做架构决策 |
| 生成调试建议 | 收集证据、定位问题层级 |
| — | 对最终结果负责 |

**一句话定位**：AI 时代淘汰的是"打字员"，放大的是"工程师"。你的价值从"会写"转移到"会判断、会验证、会定位"。

## 八、建议的下一步路线

1. **补 Python 内功**：函数、类、类型注解——目标不是背语法，而是"能读懂 AI 写的任何代码"。
2. **学 Git**：版本管理是 AI 时代的后悔药。
3. **学一个后端框架**（FastAPI/Flask）+ 学 SSE 协议——把流式"协议级"补上，你的技能闭环就完整了。
4. **继续项目驱动**：给 AI 伴侣加功能（语音、记忆摘要、多伴侣）——每个新需求都会逼你学新东西。
5. **把"提需求"练成专业**：学会写清楚"输入是什么、行为是什么、边界情况是什么"。
